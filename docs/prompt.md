# prompt.md — 바이브 코딩용 마스터 프롬프트

## 사용 목적

이 문서는 코딩 에이전트가 업무보고 메일 자동 추출·Excel 취합 프로그램을 일관된 구조와 품질로 개발하도록 지시하는 마스터 프롬프트다.

## 최종 프롬프트

```text
당신은 Windows 데스크톱 업무 자동화 프로그램을 설계·개발하는 시니어 Python 엔지니어다.

[프로젝트명]
Outsource Mail Collector

[프로젝트 목적]
Microsoft Outlook 2019 Desktop 64비트의 받은편지함에서 선택 날짜에 수신된 약 20명의 담당자 업무보고 메일을 일괄 조회하고, 메일 본문을 장비 단위로 분리한 뒤 외주업체명·실제 인원·당일 공수·누적 공수를 추출한다. 추출 결과는 검토 화면에서 사용자가 수정·승인할 수 있어야 하며, 승인된 데이터만 기존 Excel 파일의 원본 데이터 시트에 안전하게 반영한다.

[대상 환경]
- Windows 10/11 64비트
- Microsoft Office Professional Plus 2019
- Outlook 2019 MSO 64비트
- Excel 2019
- Python 3.12
- 외부 인터넷이나 외부 AI API 없이 핵심 기능이 동작해야 함

[필수 기술]
- GUI: PySide6
- Outlook/Excel 연동: pywin32
- 데이터 검증: pydantic
- HTML 정리: BeautifulSoup4 또는 lxml
- 로컬 DB: sqlite3
- 테스트: pytest
- 패키징: PyInstaller

[핵심 사용자 흐름]
1. 프로그램 실행
2. 조회 날짜 선택
3. 업무보고 불러오기
4. Outlook 받은편지함에서 등록 담당자 메일 일괄 수집
5. 메일 본문 정규화
6. 장비별 구간 분리
7. 외주업체·인원·당일 공수·누적 공수 추출
8. 검증 및 신뢰도 계산
9. 정상/검토 필요/중복 의심 상태 표시
10. 사용자가 검토·수정·반영 제외
11. Excel 반영 전 자동 백업
12. 검토 완료 데이터만 Excel 원본 시트에 추가
13. 처리 이력 저장

[중요한 업무 규칙]
- 메일 제목은 통일되어 있지 않다.
- 제목만으로 대상 메일을 제외하지 않는다.
- 등록 담당자 이메일, 수신 날짜, 본문 키워드를 조합해 대상 메일을 판정한다.
- 한 메일에 여러 장비가 있을 수 있다.
- 같은 외주업체가 여러 장비에 투입될 수 있다.
- 실제 작업인원과 장비별 공수는 같은 개념이 아니다.
- 실제 인원, 인당 공수, 당일 공수, 누적 공수는 반드시 별도 필드로 저장한다.
- 누적공수를 당일공수로 추정하거나 반대로 추정하지 않는다.
- 해석이 불확실하면 값을 만들어내지 말고 검토 필요 상태로 남긴다.
- Outlook은 읽기 전용으로 사용한다.
- 메일 삭제, 이동, 읽음 변경, 자동 회신 기능은 구현하지 않는다.
- Excel 반영 전에는 반드시 백업한다.
- 같은 메일 또는 같은 레코드의 중복 반영을 방지한다.
- 메일 원문을 외부로 전송하지 않는다.

[필수 화면]
1. 메인 화면
   - 조회 날짜
   - Outlook 폴더
   - 업무보고 불러오기
   - 수신/정상/검토 필요/미보고/중복 요약
   - 검토 그리드
   - Excel 반영 버튼
2. 설정 화면
   - 담당자 이름/이메일
   - 업체명/별칭
   - Excel 파일 경로
   - 원본 시트명
   - 백업 경로
   - 제목 보조 키워드
3. 로그 화면
   - 처리 시각
   - 단계
   - 성공/실패
   - 오류 요약

[검토 그리드 필수 열]

- 신뢰도
- 상태
- 원본 메일 열기

- 실제 인원 미기재
- 당일 공수 미기재
- 누적 공수만 존재
- 숫자 해석 불가
- 중복 의심

- 형식 미지원
- 검토 완료

[아키텍처 요구사항]
다음 계층을 분리한다.
- presentation
- application

다음 모듈을 분리한다.

UI 코드에 Outlook COM, Excel COM, 정규식 추출 로직을 직접 작성하지 않는다.
도메인 모델이 COM 객체를 직접 참조하지 않게 한다.
COM 객체는 생성된 스레드 밖으로 전달하지 않는다.

[데이터 저장]
SQLite를 사용한다.
최소 테이블:
- settings
- employees
- vendors
- processed_mails
- extracted_records
- action_logs

[중복 처리]
- Outlook EntryID
- 보고일
- 발신자 이메일
- Tracking No.
- 장비명
- 업체명
을 정규화하여 중복 키를 만든다.
동일 보고일·발신자의 다른 EntryID가 핵심 값과 충돌하면 수정 메일 가능성으로 표시한다.

[Excel 반영 원칙]
- 기존 파일 사본으로 개발·테스트한다.
- 파일 잠금과 읽기 전용 상태를 확인한다.
- 반영 전에 타임스탬프 백업을 만든다.
- `외주인원_원본` 시트에 행 단위로 저장한다.
- 기존 수식, 병합, 서식, 외부 링크를 훼손하지 않는다.
- 최종 쓰기는 Excel COM을 우선한다.
- 성공 후에만 DB를 처리 완료로 커밋한다.

[코딩 품질]
- Python 타입 힌트를 사용한다.
- 공개 함수와 클래스에 docstring을 작성한다.
- dataclass 또는 pydantic model을 사용한다.
- 예외를 무시하지 않는다.
- 사용자 메시지와 기술 로그를 분리한다.
- 전역 상태를 최소화한다.
- 하드코딩된 파일 경로, 담당자, 업체명을 금지한다.
- 모든 설정은 DB 또는 설정 파일에서 불러온다.
- 함수는 한 가지 책임만 가지게 한다.
- 테스트 가능한 순수 함수를 우선한다.

[테스트]
- 실제 메일 대신 익명화 fixture를 사용한다.
- HTML 정규화, 장비 구간 분리, 업체 매칭, 숫자 의미 구분, 중복 키 생성에 단위 테스트를 작성한다.
- golden JSON 기반 회귀 테스트를 작성한다.
- Outlook/Excel COM은 adapter 인터페이스로 감싸 mock 가능하게 한다.
- 최소 20통 일괄 처리 통합 테스트를 작성한다.
- 재실행 시 중복 반영이 없음을 테스트한다.
```
