# Tracking-No 누적 대시보드 및 최종 공수표 설계

## 목적과 화면 경계

메일에서 추출한 원본 행은 메인 검토 화면에서 계속 개별적으로 확인·수정한다.
확정 가능한 집계와 최종 공수표는 별도의 `수주 공수 대시보드`에서 관리한다.
원본 메일 검토 화면은 집계 화면으로 대체되지 않으며, 대시보드는 포함되고 삭제되지
않은 원본 행만 읽어 날짜별 집계와 누적 검증 결과를 보여준다.

## 식별자와 누적 기준

- 누적 계열의 유일한 평생 식별자는 정규화된 `Tracking No.`다. 업체명, 장비명,
  사업팀, 메일 수신일은 계열을 나누거나 보완하는 키가 아니다.
- Tracking No.가 없으면 추측하지 않으며 대시보드와 최종 확정을 차단한다.
- 각 Tracking No.에는 사용자가 명시적으로 저장한 최초 누적 기준이 필요하다.
  기준은 `기준 적용 종료일`과 하나의 10진 누적값으로 구성하며, 이유와 변경 이력을
  남긴다. 최초 기준을 계산 결과나 첫 행으로 암묵적으로 만들지 않는다.
- 기준 적용 종료일 다음 작업일부터 해당 Tracking No.의 포함·미삭제 행을 작업일과
  안정적인 원본 행 순서로 계산한다. 기준일보다 이른 원본 행은 기준을 소급 변경하지
  않으며 검토 대상으로 남긴다.

## 공수 계산과 검증

계산 당일 공수는 다음과 같다.

```text
계산 당일 공수 = 실제 작업인원 + 야근 인원 × 0.5
```

`실제 작업인원`과 `야근 인원`은 0 이상의 정수이고 야근 인원은 실제 작업인원을
초과할 수 없다. 인당 공수 표시는 전원 주간이면 `1.0`, 전원 야간이면 `1.5`,
일부만 야간이면 `혼합`이다. 가중평균 인당 공수는 만들지 않는다.

계산 누적 공수는 기준값에 날짜 순서의 확정 당일 공수를 더해 계산한다. 메일 보고
누적 공수와 계산 누적 공수가 다르면 `CUMULATIVE_MISMATCH`로 최종 확정을 차단한다.
예를 들어 기준이 2026-07-30까지 `10.0`이고 2026-07-31의 확정 당일 공수가 `2.0`이면
계산 누적은 `12.0`이다. 메일이 `11.0` 또는 `13.0`을 보고하면 불일치다. 기준이 없거나
작업일·Tracking No.·필수 숫자 근거가 없을 때도 값을 0으로 가정하지 않고 차단한다.

## 일자별 집계와 평생 누적

- 동일한 작업일과 Tracking No.의 활성 원본 행은 하나의 당일 집계 행으로 합산한다.
  이는 중복 보고를 자동으로 추측·제거한다는 뜻이 아니며, 원본 행의 검토·문제 상태와
  모든 기여 행 ID는 계속 보존한다.
- 최종 표는 작업일 + Tracking No.마다 최대 한 행을 만든다. 당일 인원과 확정 당일
  공수는 같은 날짜의 기여 행을 합산한다.
- 누적값은 그 날짜까지의 Tracking No. 평생 계열 결과다. 날짜 범위를 좁혀 미리보기
  하더라도 이전 날짜의 확정 결과와 명시적 기준은 계속 누적 계산에 사용한다.

## 가역 상태 변경과 추적성

- 포함 상태는 `제외`와 `제외 취소`를 오갈 수 있다. 제외된 행은 집계와 최종 출력에서
  빠지지만 원본과 이력은 보존한다.
- 선택 삭제는 애플리케이션 수준의 소프트 삭제다. 삭제와 복구 모두 사유, 선택한 행,
  상태 검증, 최종 스냅샷 무효화, 감사 기록, 영향받은 Tracking No. 재계산을 하나의
  트랜잭션으로 처리한다. 하나라도 실패하면 전체 변경을 롤백한다.
- 최종 스냅샷은 원본 행을 직접 출력 단위로 복제하지 않는다. 집계 행마다 모든 기여
  원본 행 ID를 보존하여 최종 값에서 원본 검토 행까지 역추적할 수 있게 한다. 이후 원본
  변경은 현재 최종 확인을 무효화하되 이미 확정된 불변 스냅샷은 고치지 않는다.

## 최종 공수표

최종 미리보기와 HTML·일반 텍스트 클립보드 표는 정확히 다음 아홉 열을 사용한다.

1. 일자
2. 거래처명
3. Tracking No.
4. 장비명
5. 사업팀
6. 실제 작업인원
7. 인당 공수
8. 투입 공수
9. 누적 공수

`야근 인원`은 원본 검토와 대시보드 드릴다운에는 남지만 최종 표의 별도 열이 아니다.
거래처명·장비명·사업팀은 표시와 매핑 검증에 쓰일 수 있어도 Tracking No. 누적 계열의
식별자를 바꾸지 않는다.

## 안전 경계와 미검증 범위

- Outlook은 날짜 범위를 명시한 읽기 전용 조회만 한다. 삭제·이동·읽음 상태 변경,
  자동 회신·전달은 하지 않는다.
- 이 공수표 경로는 Outlook 발송이나 Excel 쓰기를 수행하지 않는다. 사용자는 검토·확정
  후 클립보드 내용을 Outlook 본문에 직접 붙여 넣는다.
- 실제 Outlook, Excel, live DB, 실제 사용자 데스크톱 GUI는 별도 승인 없이는 접근하거나
  검증하지 않는다. 자동 테스트와 offscreen Qt 검증은 실환경 승인 검증을 대체하지 않는다.
- 문서·테스트·로그에는 실제 메일 본문, 주소, 개인정보 또는 회사 기밀 fixture를 넣지
  않는다.
