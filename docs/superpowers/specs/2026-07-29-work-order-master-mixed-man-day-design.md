# 수주 마스터와 혼합 야근 공수 설계

## 1. 배경과 목표

실환경 메일 확인 결과, 외주 작업 행에는 수주번호와 장비명은 있지만 업체명과
사업팀은 없는 경우가 있다. 공수 표기도 작성자마다 다르며, 확인한 형식은
`외주 인원`, `야근 인원`, `투입 공수`를 한 줄에 함께 적는다.

현재 파서는 수주번호·장비명·인원·야근 인원은 추출하지만 `투입 공수` 라벨을
인식하지 않는다. 또한 인당 공수가 없으면 취합 단계에서 이미 추출한 인원까지
유효하지 않은 값으로 처리한다.

이번 변경의 목표는 다음과 같다.

- 수주번호를 기준으로 업체와 사업팀을 안전하게 자동 입력한다.
- 메일의 `투입 공수`를 당일 보고 공수로 보존한다.
- 전체 인원 중 일부만 야근하는 경우도 장비당 한 행으로 정확히 계산한다.
- 보고값, 계산값, 사용자 확정값을 계속 분리해 보존한다.

이 설계는
`2026-07-29-work-report-compilation-design.md`의 업체 식별, 인당 공수,
투입 공수 및 최종 표 규칙을 보완한다. 충돌하는 내용은 이 문서를 우선한다.

## 2. 범위

### 2.1 포함 범위

- 수주번호·장비명·업체·사업팀·활성 상태를 관리하는 수주 마스터
- 정규화 수주번호의 정확 일치에 따른 업체·사업팀 자동 입력
- 장비명 불일치와 수주번호 미등록 검토 상태
- `투입 공수` 라벨의 당일 보고 공수 추출
- 실제 작업인원과 야근 인원의 분리 저장
- 일부 야근을 포함하는 한 행 공수 계산
- 검토 화면, 최종 스냅샷, HTML·일반 텍스트 표의 야근 인원과 혼합 표시
- 기존 DB를 보존하는 additive migration
- 익명화 fixture와 자동 회귀 테스트

### 2.2 제외 범위

- 메일 본문에서 업체 또는 사업팀을 추측하는 규칙
- 장비명 유사도나 과거 확정 행에 따른 업체 자동 추론
- 복수·범위 수주번호를 개별 번호로 임의 확장하는 기능
- 주간 인원과 야근 인원을 서로 다른 행으로 분리하는 기능
- Outlook·Excel 쓰기 또는 자동 메일 작성·발송

## 3. 선택한 접근법

### 3.1 별도 수주 마스터

기존 업체 마스터에 수주번호 목록을 넣지 않고 별도 수주 마스터를 둔다.
수주번호는 업체뿐 아니라 장비명과 사업팀까지 함께 식별하므로 독립된 업무
엔터티가 더 명확하다.

수주번호가 정확히 일치하면 마스터의 업체와 사업팀을 사용한다. 장비명은 업체
선택 키가 아니라 교차 검증 근거다. 장비명이 다르더라도 업체와 사업팀은
입력하되 경고를 남긴다.

### 3.2 실제·야근 인원 기반 한 행 계산

장비 단위 한 행을 유지하며 실제 작업인원과 야근 인원을 별도로 저장한다.
인당 공수를 모든 인원에게 동일하게 곱하는 방식 대신 다음 식으로 당일 공수를
계산한다.

```text
주간 인원 = 실제 작업인원 - 야근 인원
계산 당일 공수 = 주간 인원 × 1.0 + 야근 인원 × 1.5
               = 실제 작업인원 + 야근 인원 × 0.5
```

메일의 `투입 공수`는 이 계산값으로 대체하지 않고
`reported_daily_man_day`에 그대로 보존한다.

## 4. 아키텍처와 책임

### 4.1 parsing

파서는 Outlook, SQLite 또는 수주 마스터를 알지 못한다.

- 장비 섹션에서 수주번호와 장비명을 추출한다.
- `외주 인원`에서 실제 작업인원을 추출한다.
- 명시된 `야근` 인원은 `night_headcount`로 추출한다.
- `투입 공수`는 `daily_man_day`로 추출한다.
- 업체와 사업팀은 메일에 없으면 `None`으로 둔다.

`투입 공수`와 `누적 공수`는 라벨 의미가 다르므로 서로 대입하지 않는다.
`총 공수`처럼 당일·누적 의미가 불명확한 기존 표기는 계속 원문 근거만 남기고
숫자 필드를 추정하지 않는다.

### 4.2 application

신규 `WorkOrderMappingService`가 수주 마스터 조회와 검증을 담당한다.

- 입력: 추출한 수주번호와 장비명
- 출력: 업체, 사업팀, 매핑 상태 및 경고 코드
- 의존성: 저장소 인터페이스
- 비의존성: Outlook, PySide6

`ExtractionOrchestrator`는 순수 추출 흐름을 유지한다.
`WorkReportService`는 추출 레코드를 취합 행으로 변환할 때
`WorkOrderMappingService`의 결과를 적용하고 공수를 계산한다.

`ManDayCalculationService`는 실제 작업인원, 야근 인원 및 메일 보고 공수를 받아
계산값과 불일치 경고를 반환한다. 누적 공수 계산 규칙은 기존 설계를 유지한다.

### 4.3 infrastructure

SQLite 저장소는 수주 마스터 CRUD, 정규화 키 중복 검사 및 신규 행 필드를
제공한다. DB 변경은 기존 테이블과 데이터를 삭제하지 않는 additive migration으로
구현한다.

### 4.4 UI

설정 대화상자에 `수주 마스터` 탭을 추가한다.

- 수주번호
- 장비명
- 업체
- 사업팀
- 활성

업체는 기존 활성 업체 마스터에서 선택한다. 사업팀은 빈 문자열이 아닌
사용자 입력값으로 저장한다.

검토 화면과 수동 행 화면에는 `야근 인원`을 추가한다. 최종 표에도
`실제 작업인원` 다음에 `야근 인원`을 표시한다.

## 5. 수주 마스터 데이터 모델과 매핑

논리 엔터티 `WorkOrderMapping`은 다음 필드를 가진다.

- 내부 매핑 ID
- 원문 수주번호
- 정규화 수주번호
- 장비명
- 업체 ID 및 표시용 표준 업체명
- 사업팀
- 활성 여부
- 생성·수정 시각

정규화는 Unicode NFKC, 앞뒤 공백 제거, 내부 공백 제거, 영문 대문자화를 적용한다.
활성 매핑의 정규화 수주번호에는 고유 제약을 둔다. 같은 수주번호를 다른 업체나
사업팀으로 중복 등록할 수 없다.

매핑 규칙:

1. 수주번호가 없으면 자동 매핑하지 않고 기존 식별 오류를 유지한다.
2. 활성 수주번호가 정확히 일치하면 업체와 사업팀을 채운다.
3. 장비명도 정규화해 비교한다.
4. 장비명이 일치하면 정상 매핑이다.
5. 장비명이 다르면 업체·사업팀은 채우고 `EQUIPMENT_MAPPING_MISMATCH` 경고를
   추가한다.
6. 수주번호가 미등록이면 `WORK_ORDER_UNREGISTERED` 차단 코드를 추가한다.
7. 복수·범위 수주번호 문자열은 전체 정규화 값으로 등록된 경우에만 자동
   매핑한다. 등록되지 않은 표현을 개별 수주번호로 추측·확장하지 않는다.

마스터를 새로 저장했을 때 업체 또는 사업팀이 비어 있는 미확정 메일 행에는
매핑을 다시 적용할 수 있다. 사용자가 이미 수정·확정한 값은 자동으로 덮어쓰지
않는다.

## 6. 공수 추출과 계산

### 6.1 추출

다음 표기를 당일 보고 공수로 인식한다.

```text
투입 공수 : 1.5
투입공수: 3
```

공백, 일반 콜론과 전각 콜론, 정수와 소수를 허용한다. `투입 공수` 값은
`daily_man_day`에 저장한다.

실제 작업인원과 야근 인원은 각각 별도 필드로 보존한다. 야근 인원 표기가
명시되지 않았으면 숫자를 추정하지 않는다. 명시적으로 `야근 0명`이라고 적힌
경우에만 0으로 확정한다.

### 6.2 유효성

- 실제 작업인원은 0 이상의 정수여야 한다.
- 야근 인원은 0 이상의 정수여야 한다.
- 야근 인원은 실제 작업인원보다 클 수 없다.
- 야근 인원이 명시되지 않으면 자동 계산을 확정하지 않고
  `NIGHT_HEADCOUNT_UNRESOLVED` 경고를 표시한다.
- 보고 당일 공수는 0 이상의 유한한 `Decimal`이어야 한다.

### 6.3 인당 공수 표시

- 야근 인원 0명: `1.0`
- 야근 인원과 실제 작업인원이 같음: `1.5`
- 야근 인원이 0명보다 많고 실제 작업인원보다 적음: `혼합`
- 야근 인원 미확인: `확인 필요`

혼합 상태는 정상적인 업무 상태이며 그 자체로 최종 확정을 차단하지 않는다.
숫자 하나의 가중평균 인당 공수는 저장하거나 표시하지 않는다.

### 6.4 보고값 대조

- 계산 당일 공수와 메일 보고 당일 공수가 같으면 계산값을 확정 후보로 사용한다.
- 메일 보고값이 없으면 계산값을 후보로 두고 `DAILY_MISSING` 경고를 표시한다.
- 두 값이 다르면 두 값을 모두 보존하고 `DAILY_MISMATCH` 경고를 표시한다.
- 불일치 값을 자동 보정하거나 어느 한쪽으로 덮어쓰지 않는다.
- 정상 인원 값은 다른 공수 필드의 오류 때문에 `None`으로 바꾸지 않는다.

## 7. 취합 행과 최종 스냅샷

`WorkReportRow`에는 다음 필드를 추가하거나 의미를 보완한다.

- `night_headcount`
- `per_person_man_day`: 전원 주간 또는 전원 야근일 때만 숫자
- 혼합·미확인 표시는 실제 인원과 야근 인원에서 파생

혼합 행에서는 `per_person_man_day`가 `None`이어도 필수값 누락으로 보지 않는다.
대신 실제 인원, 야근 인원, 확정 당일 공수 및 누적 공수가 유효해야 한다.

최종 스냅샷도 야근 인원을 보존한다. 최종 표 열 순서는 다음과 같다.

1. 일자
2. 거래처명
3. Tracking No.
4. 장비명
5. 사업팀
6. 실제 작업인원
7. 야근 인원
8. 인당 공수
9. 투입 공수
10. 누적 공수

HTML과 일반 텍스트 렌더러는 혼합 행의 인당 공수를 `혼합`으로 출력한다.

## 8. 오류·경고와 확정 조건

신규 차단 코드:

- `WORK_ORDER_UNREGISTERED`: 수주번호가 수주 마스터에 없음
- `NIGHT_HEADCOUNT_INVALID`: 야근 인원이 음수, 정수가 아니거나 실제 인원보다 큼

신규 확인 경고:

- `EQUIPMENT_MAPPING_MISMATCH`: 메일 장비명과 수주 마스터 장비명이 다름
- `NIGHT_HEADCOUNT_UNRESOLVED`: 야근 인원이 명시되지 않아 계산 근거가 불완전함

수주 미등록과 유효하지 않은 야근 인원은 값이 해결될 때까지 최종 확정을
차단한다. 장비명 불일치와 야근 인원 미확인은 사용자가 원문과 값을 확인하고
명시적으로 확정할 수 있다.

## 9. 영속성과 호환성

신규 `work_order_mappings` 테이블을 추가한다. 기존 업체 마스터는 표준 업체명,
별칭 및 최종 정렬 순서의 소유자로 유지한다.

기존 테이블에는 필요한 열만 추가한다.

- `work_report_rows.night_headcount`
- `final_report_rows.night_headcount`

`extracted_records.night_headcount`는 이미 존재하므로 재사용한다. application DTO가
이 값을 누락하지 않도록 전달 경계를 보완한다.

기존 행의 신규 열은 `NULL`로 유지한다. 이를 임의로 주간 0명으로 바꾸지 않는다.
기존 최종 스냅샷은 변경하지 않으며 신규 출력에서 야근 인원은 빈칸으로 표시한다.

## 10. 테스트 전략

### 10.1 익명화 파서 회귀

- 수주번호와 장비명 추출
- `1명 / 야근 1명 / 투입 공수 1.5`
- `2명 / 야근 2명 / 투입 공수 3`
- `3명 / 야근 1명 / 투입 공수 3.5`
- 공백·콜론 변형
- `총 공수`가 계속 불명확 값으로 남는지 확인

### 10.2 계산 단위 테스트

- 전원 주간, 전원 야근, 일부 야근
- 야근 인원이 실제 인원보다 큰 값 차단
- 보고 당일 공수 일치·누락·불일치
- 공수 오류가 정상 실제 인원을 지우지 않음
- 혼합 행의 인당 공수 숫자 미생성 및 확정 가능 조건

### 10.3 수주 마스터 테스트

- CRUD와 정규화 수주번호 중복 방지
- 수주번호 정확 일치에 따른 업체·사업팀 입력
- 장비명 불일치 경고
- 미등록 수주번호 차단
- 비활성 매핑 제외
- 기존 사용자 수정값 비덮어쓰기
- 구버전 DB additive migration

### 10.4 UI·출력 테스트

- 수주 마스터 탭 저장·재조회
- 야근 인원 검토·수동 행 편집
- 혼합 인당 공수 표시
- 최종 표 야근 인원 열
- HTML과 일반 텍스트 값 일치
- 작업일별 반복 머리글 유지

### 10.5 실환경 검증

자동 테스트가 통과한 뒤 사용자 승인 하에 새 테스트 DB 복제본을 사용한다.
2026-07-27 메일을 읽기 전용으로 다시 수집하고 다음을 확인한다.

- 수주번호·장비명·인원·야근 인원·투입 공수
- 수주 마스터의 업체·사업팀 적용
- 보고 당일 공수와 계산값 일치
- Outlook 읽음 상태 비변경
- 실제 Excel·Outlook 쓰기 미수행

## 11. 완료 조건

- 수주 마스터를 설정 화면에서 관리할 수 있다.
- 등록 수주번호에 따라 업체와 사업팀이 자동 입력된다.
- `투입 공수`가 당일 보고 공수로 추출된다.
- 실제 작업인원과 야근 인원이 분리 보존된다.
- 일부 야근도 한 행에서 정확한 당일 공수로 계산된다.
- 전원 주간은 `1.0`, 전원 야근은 `1.5`, 일부 야근은 `혼합`으로 표시된다.
- 공수 오류가 정상 인원 값을 삭제하지 않는다.
- 혼합 행이 숫자 인당 공수 누락만으로 차단되지 않는다.
- 기존 DB와 최종 스냅샷이 additive migration으로 보존된다.
- 관련 자동 테스트와 승인된 Outlook 읽기 전용 실환경 검증이 통과한다.
