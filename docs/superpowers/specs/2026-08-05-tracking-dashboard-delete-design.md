# Tracking No. 개별 삭제 설계

## 목표

수주 공수 대시보드에서 선택한 Tracking No.의 운영 데이터를 사용자가 확인한 뒤 삭제한다. 프로젝트 설정 데이터는 보존한다.

## 범위

- 대시보드에 빨간색 배경의 `삭제` 버튼을 추가한다.
- 삭제는 선택한 Tracking No. 하나에만 적용한다.
- 삭제 전 확인 대화상자에서 대상 Tracking No.와 삭제 영향을 안내한다.
- 취소하면 데이터를 변경하지 않는다.
- 성공하면 대시보드와 호출 화면을 새로고침한다.

## 데이터 경계

삭제 대상은 선택한 Tracking No.에 연결된 수집·추출·검토·대시보드·최종표 운영 데이터다. 원본 메일은 다른 Tracking No.의 행이 더 이상 참조하지 않을 때만 함께 삭제한다.

다음 프로젝트 설정 데이터는 삭제하지 않는다.

- 앱 설정
- 직원
- 업체
- 수주 매핑

## 구성

### Repository

단일 트랜잭션에서 Tracking No.별 운영 데이터를 삭제하는 명시적 메서드를 제공한다. 삭제 도중 오류가 나면 전체 변경을 롤백한다.

### Application service

대시보드 서비스가 Tracking No.를 정규화하고, 존재 여부를 확인한 뒤 repository 삭제 메서드를 호출한다. 존재하지 않는 대상은 사용자에게 표시할 수 있는 오류로 변환한다.

### UI

`TrackingDashboardDialog`의 작업 영역에 `삭제` 버튼을 배치한다. 버튼은 빨간색 바탕과 흰 글자로 강조한다. 선택된 Tracking No.가 없으면 안내 메시지를 표시한다. `QMessageBox.question`에서 명시적으로 확인한 경우에만 서비스를 호출한다.

## 검증

- 서비스: 대상 Tracking No.의 운영 데이터만 삭제하고 설정 및 다른 Tracking No. 데이터는 보존한다.
- Repository: 삭제가 원자적이며 공유 원본 메일을 보존한다.
- UI: 버튼의 강조 스타일, 미선택 안내, 취소 시 무변경, 확인 시 서비스 호출과 새로고침을 검증한다.
- 실제 Outlook, Excel, live DB는 테스트하지 않는다.
