## ADR-011 상세 공수표 스냅샷과 클립보드 출력

**상태**: 승인

**결정**:

- 상단 인원 요약표가 아니라 장비별 상세 외주 공수표만 자동 취합한다.
- 제목 날짜를 작업일의 우선 근거로 사용하고 본문·수신일은 교차 검증한다.
- 투입·누적 공수의 메일 보고값, 계산값, 사용자 확정값을 분리한다.
- 누적 계열은 정규화 Tracking No. 하나로 관리한다. Tracking No.가 없으면
  장비명·업체명으로 보완하거나 추측하지 않고 최종 확정을 차단한다.
- 최초 누적 기준과 중복·수정 보고는 사용자 결정을 요구한다.
- 최종 확인 결과는 불변 DB 스냅샷으로 저장하고 HTML/일반 텍스트를
  클립보드에 함께 복사한다.

**이유**:

- 공수는 단순 인원 합계가 아니므로 계산 근거와 메일 작성 오류를 함께 검증해야
  한다.
- 사용자가 Outlook에서 최종 메일을 직접 작성·발송하는 기존 통제점을 유지한다.
- 스냅샷을 사용하면 이후 원본 수정이 이미 확인한 보고 내용을 조용히 바꾸지
  않는다.

**제약**:

- Outlook은 읽기 전용이다.
- 이 경로는 Excel을 쓰지 않는다.
- 실제 Outlook 붙여 넣기 모양은 별도 사용자 승인 아래 실환경에서 검증한다.

**이유** - 리스크 최소화 - 실제 메일 기반 규칙 보완

## ADR-012 수주번호 exact mapping과 혼합 야근 공수

**상태**: 승인

**결정**:

- 정규화 수주번호의 정확 일치만 업체와 사업팀의 자동 입력 근거로 사용한다.
- 장비명 불일치는 경고로 남기되 정확한 수주번호 매핑을 대체하지 않는다.
- 메일의 `투입 공수`는 당일 보고 공수로 보존하고, 계산 당일 공수는
  `실제 작업인원 + 야근 인원 × 0.5`로 별도 산정한다.
- 인당 공수는 전원 주간 `1.0`, 전원 야근 `1.5`, 일부 야근 `혼합`으로
  표시한다. `야근 인원`은 원본/대시보드 검토에 남기되 최종 표는 아홉 열의 집계
  출력으로 제한한다.
- 수주번호 미등록과 유효하지 않은 야근 인원은 최종화를 차단한다.

**이유**:

- 수주번호는 업체와 사업팀을 결정하는 업무 식별자이며 장비명 표기 차이가
  정확한 매핑 결과를 조용히 바꾸어서는 안 된다.
- 일부 인원만 야근하는 정상 업무를 한 행으로 유지하면서 보고값과 계산값을
  독립적으로 대조해야 한다.

**제약**:

- 등록되지 않은 수주번호, 장비명 유사도 또는 과거 행에서 업체·사업팀을
  추측하지 않는다.
- `투입 공수` 불일치를 자동 보정하지 않으며 Outlook·Excel 쓰기를 추가하지
  않는다.

## ADR-013 Tracking No. 누적 대시보드와 가역 집계

**상태**: 승인

**결정**:

- 메일 원본 행 검토와 Tracking No. 집계 관리를 분리한다. 원본 행은 계속 개별 검토하고,
  별도 대시보드가 포함·미삭제 원본 행을 날짜별로 집계한다.
- 누적 계열은 정규화 Tracking No.만 사용한다. 각 계열의 최초 누적은 기준 적용 종료일과
  값이 명시된 기준으로 시작하며, 이후 행을 작업일과 원본 행 순서로 계산한다.
- 같은 작업일·Tracking No. 기여 행은 하나의 당일 집계 행으로 합산한다. 최종 스냅샷은
  집계 행과 모든 기여 원본 행 ID를 함께 저장한다.
- 메일 누적과 계산 누적의 불일치, Tracking No. 누락, 기준 누락, 필수 숫자·날짜 문제는
  최종화를 차단한다.
- 제외는 가역 토글이고, 선택 삭제와 복구는 사유·감사 이력·재계산·스냅샷 무효화를
  포함하는 원자적 소프트 삭제 작업이다.

**이유**:

- 같은 수주번호의 여러 메일 행을 원본 검토에서 잃지 않으면서도, 최종 보고에는
  날짜별로 하나의 추적 가능한 집계 행이 필요하다.
- 업체나 장비 표기의 변화가 평생 누적 계열을 분리하거나 조용히 합쳐서는 안 된다.
- 가역 상태와 기여 원본 행 연결은 사용자의 정정·감사·복구 요구를 충족한다.

**제약**:

- Outlook은 읽기 전용이며 이 경로는 Excel 쓰기 또는 Outlook 자동 발송을 추가하지
  않는다.
- 실제 Outlook, Excel, live DB, 실제 데스크톱 GUI 검증은 별도 승인 아래에서만 한다.
