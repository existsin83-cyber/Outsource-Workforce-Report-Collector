# ADR.md --- Architecture Decision Record

## 목적

이 문서는 프로젝트의 주요 아키텍처 및 기술적 의사결정을 기록한다.
SYSTEM_ARCHITECTURE.md가 시스템 구조(What)를 설명한다면, ADR은 설계
이유(Why)를 기록한다.

------------------------------------------------------------------------

## ADR-001 Outlook COM 사용

**결정**: Outlook 2019 Desktop COM(Object Model) 사용

**이유** - Outlook 2019 Desktop 환경과 가장 잘 맞음 - 기존 업무 흐름
변경 없음 - 받은편지함 직접 조회 가능 - .msg 저장 불필요

**대안** - Microsoft Graph API - Power Automate - .msg 분석

------------------------------------------------------------------------

## ADR-002 받은편지함 직접 조회

**결정**: 날짜 + 등록 담당자 기준으로 받은편지함을 일괄 조회

**이유** - 메일 제목이 통일되어 있지 않음 - 담당자 기준이 가장 안정적

## ADR-011 상세 공수표 스냅샷과 클립보드 출력

**상태**: 승인

**결정**:

- 상단 인원 요약표가 아니라 장비별 상세 외주 공수표만 자동 취합한다.
- 제목 날짜를 작업일의 우선 근거로 사용하고 본문·수신일은 교차 검증한다.
- 투입·누적 공수의 메일 보고값, 계산값, 사용자 확정값을 분리한다.
- 누적 계열은 업체명과 Tracking No.를 사용하며 Tracking No.가 없을 때만
  장비명을 보완 키로 사용한다.
- 최초 누적 기준과 중복·수정 보고는 사용자 결정을 요구한다.
- 최종 확인 결과는 불변 DB 스냅샷으로 저장하고 HTML/일반 텍스트를
  클립보드에 함께 복사한다.

**이유**:

- 공수는 단순 인원 합계가 아니므로 계산 근거와 메일 작성 오류를 함께 검증해야
  한다.
- 사용자가 Outlook에서 최종 메일을 직접 작성·발송하는 기존 통제점을 유지한다.
- 스냅샷을 사용하면 이후 원본 수정이 이미 확인한 보고 내용을 조용히 바꾸지
  않는다.

**제약**:

- Outlook은 읽기 전용이다.
- 이 경로는 Excel을 쓰지 않는다.
- 실제 Outlook 붙여 넣기 모양은 별도 사용자 승인 아래 실환경에서 검증한다.

**이유** - 리스크 최소화 - 실제 메일 기반 규칙 보완
