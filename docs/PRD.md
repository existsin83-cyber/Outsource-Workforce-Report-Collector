# PRD — 업무보고 메일 내 외주 인원 자동 추출·Excel 취합 프로그램

## 1. 문서 목적

본 문서는 Outlook 2019 받은편지함에 수신되는 다수 담당자의 일일 업무보고 메일을 자동으로 수집·분석하여, 외주업체별 작업 인원과 장비별 공수 정보를 검토 후 기존 Excel 집계표에 반영하는 Windows 전용 업무 프로그램의 제품 요구사항을 정의한다.

---

## 2. 배경 및 문제

현재 약 20명의 담당자가 하루 한 통씩 업무보고 메일을 발송한다. 취합 담당자는 하루 약 20통의 메일을 개별 확인하고, 장비별 외주업체명·실제 인원·당일 공수·누적 공수를 판독하여 기존 Excel 집계표에 수작업으로 입력한다.

메일 제목은 통일되어 있지 않다.

- 전장 기술 업무보고
- 전장 기술팀 업무보고
- 전장 기술 업무보고서
- 일일 업무 보고
- 기타 유사 표현

수작업 과정에서는 다음 문제가 발생한다.

- 메일 확인 및 전사에 많은 시간 소요
- 누락·중복·숫자 오입력 가능성
- 당일 공수와 누적 공수 혼동 가능성
- 같은 업체가 여러 장비에 투입될 때 중복 집계 가능성
- 수정 메일 재수신 시 기존 데이터와 충돌 가능성
- 담당자 미보고 여부 확인이 번거로움

---

## 3. 제품 목표

### 3.1 핵심 목표

1. 선택한 날짜의 업무보고 메일을 Outlook에서 일괄 조회한다.
2. 메일 본문을 장비 단위로 구분한다.
3. 외주업체명, 실제 인원, 당일 공수, 누적 공수를 추출한다.
4. 추출 결과를 검토 화면에서 확인·수정할 수 있게 한다.
5. 승인된 데이터만 Excel 원본 데이터 시트에 반영한다.
6. 같은 메일 또는 같은 데이터를 중복 반영하지 않는다.
7. 미보고 담당자를 자동 표시한다.

### 3.2 비목표

초기 버전에서는 다음을 구현하지 않는다.

- 메일 실시간 상시 감시
- 검토 없이 완전 자동 반영
- 외부 AI API 기본 연동
- 모바일 앱 또는 웹 시스템
- 자동 회신·독촉 메일 발송
- 사내 서버 배포
- 장기 통계·BI 대시보드

---

## 4. 사용자

### 4.1 주 사용자

- 업무보고 취합 담당자
- 매일 Outlook과 Excel을 사용하는 Windows 사용자

### 4.2 보조 사용자

- 팀장 또는 관리자
- 추출 규칙과 업체 목록을 관리하는 담당자

---

## 5. 사용자 시나리오

### 5.1 정상 시나리오

1. 사용자가 프로그램을 실행한다.
2. 조회 날짜를 선택한다.
3. `업무보고 불러오기`를 누른다.
4. 프로그램이 Outlook 받은편지함에서 대상 메일을 수집한다.
5. 메일별 장비 정보와 외주 인원·공수를 추출한다.
6. 정상 항목과 검토 필요 항목을 구분해 표시한다.
7. 사용자가 오류 항목을 수정하거나 반영 제외한다.
8. `Excel 반영`을 누른다.
9. 프로그램이 백업을 만든 후 Excel 원본 데이터 시트에 저장한다.
10. 처리 이력과 로그를 기록한다.

### 5.2 미보고 확인 시나리오

1. 등록된 담당자 20명과 해당 날짜의 수신 메일 발신자를 비교한다.
2. 메일이 없는 담당자를 `미보고`로 표시한다.
3. 사용자는 미보고 목록만 확인한다.

### 5.3 수정 메일 시나리오

1. 동일 담당자가 같은 날짜의 수정본을 보낸다.
2. 프로그램이 기존 처리 메일과 비교한다.
3. `수정 가능성` 또는 `중복 의심` 상태로 표시한다.
4. 사용자가 기존 값 유지, 덮어쓰기, 별도 행 추가 중 하나를 선택한다.

## 6. 기능 요구사항

## FR-01 Outlook 연결

- Outlook 2019 Desktop 64비트 환경을 지원해야 한다.
- 현재 로그인된 Outlook 프로필을 사용해야 한다.
- 기본 동작은 읽기 전용이어야 한다.
- 받은편지함 또는 설정된 하위 폴더를 조회할 수 있어야 한다.
- Outlook이 실행 중이 아니면 실행 또는 연결 안내를 제공해야 한다.

## FR-02 메일 수집

- 사용자가 선택한 날짜의 메일만 조회해야 한다.
- 등록된 담당자 목록을 기준으로 대상 메일을 우선 필터링해야 한다.
- 제목은 보조 조건으로 사용하되, 제목 불일치만으로 제외해서는 안 된다.
- 메일의 제목, 발신자, 수신 시각, 본문, 고유 식별값을 읽어야 한다.
- 하루 20통 이상의 메일을 일괄 처리할 수 있어야 한다.

## FR-03 담당자 관리

- 담당자 이름과 이메일 주소를 등록·수정·삭제할 수 있어야 한다.
- 담당자별 활성/비활성 상태를 관리해야 한다.
- 선택 날짜 기준 미보고 담당자를 표시해야 한다.

## FR-04 메일 본문 정규화

- HTML 메일을 텍스트 구조로 변환해야 한다.
- 표, 줄바꿈, 특수 공백을 정규화해야 한다.
- 원본 본문은 별도로 유지해야 한다.
- 본문 정규화 과정에서 숫자와 장비 구분 정보가 손실되면 안 된다.

## FR-05 장비 구간 분리

- 번호 제목, 수주번호, Tracking No., 장비명 패턴을 활용해 본문을 장비 단위로 구분해야 한다.
- 한 메일에 여러 장비가 포함되어도 각각 별도 레코드로 생성해야 한다.
- 구간 분리가 불확실하면 `검토 필요` 상태로 표시해야 한다.

## FR-06 외주 정보 추출

다음 필드를 추출해야 한다.

- 거래처
- Tracking No.
- 수주번호
- 장비명
- 호기
- 사업팀
- 외주업체명
- 실제 작업인원
- 주간 인원
- 야간 인원
- 주간 공수
- 야간 공수
- 인당 공수
- 당일 투입 공수
- 누적 공수
- 비고

## FR-07 숫자 의미 구분

- `실제 인원`, `인당 공수`, `당일 공수`, `누적 공수`를 별도 필드로 저장해야 한다.
- `누적`, `누계`, `총 공수`와 같은 표현은 누적 공수 후보로 분류해야 한다.
- `주간`, `야간`, `당일`은 당일 공수 후보로 분류해야 한다.
- 문맥이 불명확하면 임의 확정하지 말고 검토 대상으로 남겨야 한다.

## FR-08 업체명 관리

- 외주업체 마스터 목록을 관리할 수 있어야 한다.
- 업체 별칭과 오타 변형을 등록할 수 있어야 한다.
- 업체명 미확인 시 원문 후보를 표시해야 한다.

## FR-09 검토 화면

검토 표에는 최소 다음 열이 있어야 한다.

- 선택
- 보고일
- 작성자
- 장비명
- Tracking No.
- 외주업체
- 실제 인원
- 당일 공수
- 누적 공수
- 상태
- 원본 메일 열기

- 셀 직접 수정

- 상태 변경

- 수정본 처리 방식 선택

## FR-10 상태 판정

최소 다음 상태를 지원해야 한다.

- 정상
- 장비명 미확인

- 업체명 미확인
- 실제 인원 미기재
- 당일 공수 미기재

## FR-11 Excel 반영

- 사용자가 지정한 Excel 파일을 열어야 한다.
- 반영 전 자동 백업을 생성해야 한다.
- `외주인원_원본` 시트에 행 단위로 저장해야 한다.
- 기존 수식과 서식을 훼손하지 않아야 한다.
- Excel 파일이 다른 사용자에게 열려 있거나 잠겨 있으면 안전하게 중단해야 한다.
- 처리 성공·실패 결과를 사용자에게 표시해야 한다.

## FR-12 중복 방지

다음 값을 이용해 중복 키를 생성해야 한다.

- Outlook 메일 고유 ID
- 보고일
- 작성자
- Tracking No.
- 장비명
- 외주업체
- 당일 공수

같은 메일을 재조회해도 자동으로 중복 입력되면 안 된다.

## FR-13 처리 이력

- 메일 조회 시각
- 메일 고유 ID
- 추출 결과
- 사용자가 수정한 값
- Excel 반영 시각
- 반영 성공 여부
- 오류 메시지

를 기록해야 한다.

## 7. 비기능 요구사항

### 7.1 성능

- 하루 20~50통 수준의 메일을 30초 이내에 1차 분석하는 것을 목표로 한다.
- 사용자 화면은 분석 중 응답 없음 상태가 되지 않아야 한다.

### 7.2 안정성

- 메일 읽기는 기본적으로 읽기 전용이어야 한다.
- Excel 반영 전 백업은 필수다.
- 오류 발생 시 부분 저장 여부를 명확히 표시해야 한다.

### 7.3 보안

- 메일 원문을 외부 서버로 전송하지 않는다.
- 외부 AI API는 기본 비활성화한다.
- 계정 비밀번호를 저장하지 않는다.
- Outlook 현재 로그인 세션만 사용한다.

### 7.4 유지보수성

- 업체명, 담당자, 키워드, 추출 규칙을 코드 수정 없이 설정 파일에서 변경할 수 있어야 한다.
- 분석기, Outlook 연결부, Excel 저장부를 분리해야 한다.
- 로그에서 실패 원인을 추적할 수 있어야 한다.

### 7.5 사용성

- 일상 사용 흐름은 `불러오기 → 검토 → Excel 반영`으로 단순화한다.
- 검토 필요 항목은 시각적으로 구분한다.
- 기술 지식이 없는 사용자도 사용할 수 있어야 한다.

## 12. 현재 구현 범위 — 상세 외주 공수표 취합

2026-07-29 승인 범위에서는 상단의 지역·업체별 인원 요약표를 제외하고, 장비별
상세 외주 공수표만 취합한다. 지역 분류와 카카오톡 인원 취합은 이 기능의 범위가
아니다.

- Outlook은 읽기 전용으로 메일을 수집하며 초안 작성·전송을 하지 않는다.
- 작업일은 메일 제목의 날짜를 우선 사용한다. 본문 날짜와 수신일은 교차 검증
  근거이며 불일치는 `확인 필요`로 표시한다.
- 제목 날짜가 없으면 본문 날짜를 후보로만 제시하고, 둘 다 없으면 수신일로
  추정하지 않는다.
- 실제 작업인원, 인당 공수, 메일 투입 공수, 계산 투입 공수, 확정 투입 공수,
  메일 누적 공수, 계산 누적 공수, 확정 누적 공수를 서로 분리해 보존한다.
- 수주번호는 수주 마스터의 정규화 값과 정확히 일치할 때만 업체와 사업팀을
  자동 입력한다. 장비명 불일치는 검토 경고를 남기되 정확히 일치한 수주번호
  매핑을 대체하거나 취소하지 않는다.
- 메일의 `투입 공수`는 당일 보고 공수로 보존한다. 실제 작업인원과 야근
  인원을 분리하고, 계산 당일 공수는
  `실제 작업인원 + 야근 인원 × 0.5`로 산정한다.
- 인당 공수는 전원 주간 `1.0`, 전원 야근 `1.5`, 일부 야근 `혼합`으로
  표시하며 가중평균 숫자를 만들지 않는다.
- 누적 계열은 `정규화 업체명 + Tracking No.`를 기본 키로 사용하고 Tracking
  No.가 없을 때만 정규화 장비명을 사용한다.
- 최초 누적 기준이 없으면 값을 추정하지 않고 사용자 확인 전까지 최종 확정을
  차단한다.
- 주말·예외 작업은 수동 행으로 추가하며 동일한 계산·중복·누적 검증을 적용한다.
- 동일 작업일·업체·Tracking No. 후보는 자동 합산하지 않고 사용자가 기존 유지,
  새 보고 사용, 둘 다 제외 중 하나를 선택한다.
- 최종 확인된 행은 불변 스냅샷으로 저장하고, 작업일별 반복 머리글이 있는
  HTML과 탭 구분 일반 텍스트를 클립보드에 함께 복사한다.
- 최종 상세 표는 `실제 작업인원` 다음에 `야근 인원` 열을 포함한다.
- 수주번호 미등록 또는 유효하지 않은 야근 인원은 값이 해결될 때까지 최종
  확정을 차단한다.
- 현재 단계에서는 Outlook 메일 본문에 사용자가 직접 붙여 넣는다. Excel 쓰기
  기능은 활성화하지 않으며 기존 준비 중 안내를 유지한다.
- 배포 방식: Python 설치형 또는 단일 실행 파일
